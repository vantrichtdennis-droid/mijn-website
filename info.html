Over dit project

Oriëntatie: idee en doel van de site

Het project begon niet technisch, maar inhoudelijk. Ik wilde een eenvoudige website maken die gebruikers met ADHD helpt om taken te verkleinen en focus te behouden. De kern was bewust níet allesomvattend, maar gericht op rust, overzicht en dwingende eenvoud. Dit uitgangspunt bepaalde later veel technische keuzes.

Eerste kennismaking met HTML-bestanden

Ik begon met losse bestanden zoals index.html, later gevolgd door tool.html en zo-werkt-het.html. Al snel liep ik vast doordat Windows bestandsextensies verbergt. HTML-bestanden werden onbedoeld .txt. Dit bleek geen programmeerfout, maar een systeeminstelling. Ik leerde hier dat problemen niet altijd in de code zitten, maar soms in de omgeving.

Eerst structuur, nog geen functionaliteit

De pagina’s werden eerst opgebouwd zonder dynamiek. Ik ontdekte dat HTML vooral gaat over structuur en inhoud, en dat een website ook zonder JavaScript al betekenisvol kan zijn. Dat gaf rust en overzicht.

CSS als aparte laag leren begrijpen

Bij het toevoegen van <style> raakte ik in de war over waar code thuishoort. Door CSS soms verkeerd te plaatsen, werd duidelijk dat CSS beschrijft hoe iets eruitziet en geen acties uitvoert. Dit onderscheid moest ik letterlijk al doende leren.

Navigatie en meerdere pagina’s koppelen

Door pagina’s met elkaar te verbinden via <a href> begreep ik dat een website bestaat uit losse bestanden die samen één geheel vormen. Kleine typfouten zorgden meteen voor fouten, wat precisie ineens heel concreet maakte.

JavaScript introduceren

JavaScript kwam pas later. Ik twijfelde of dit niet te complex zou worden, maar door klein te beginnen (een knop met onclick) werd duidelijk wat “dynamisch” eigenlijk betekent: reageren op gebruikersgedrag.

Eerste echte bug: dubbele functies

Op de tool-pagina werkte de code niet goed doordat dezelfde functie twee keer bestond. De site deed iets, maar niet wat ik verwachtte. Dit maakte scherp dat code niets “interpreteert”: dubbel is fout.

Oplossing door schrappen

Het probleem werd niet opgelost door meer code toe te voegen, maar door code te verwijderen. Dat inzicht was belangrijk: eenvoud is soms de echte oplossing.

UX-aanpassingen

Met hover-effecten, markeringen en animatie zag ik hoe kleine technische ingrepen grote invloed hebben op gebruikerservaring. Mijn focus verschoof van “werkt het?” naar “wat doet dit met de gebruiker?”

De ‘over’-pagina als reflectie

De website werd ook een plek om mijn eigen leerproces te beschrijven. Daarmee werd de site niet alleen een product, maar ook een reflectiemiddel.

Verwarring rond body

De navigatiebalk gedroeg zich anders op één pagina. Door fouten, dubbele <body>-tags en verkeerd geplaatste CSS begreep ik uiteindelijk dat alles wat zichtbaar is binnen body valt, inclusief de navigatie.

Vergelijken als strategie

Ik begon pagina’s naast elkaar te leggen en verschillen in code te analyseren. Dit deed ik zelfstandig. Hier merkte ik dat ik niet meer alleen uitvoerde, maar echt problemen oploste.

Inzicht in scrollbalken

Ik ontdekte dat een verticale scrollbalk invloed heeft op centrering en layout. Dat was een belangrijk inzicht: niet elk verschil komt door mijn code, soms door de browser.

Van losse regels naar hiërarchie

Ik begon te begrijpen dat body de basis vormt, p automatisch volgt en elementen als nav en h1 daarvan kunnen afwijken. Dat gaf structuur aan mijn denken over code.

Afronding: durven rommelen

Ik maakte fouten, haalde dingen weg, zette ze terug en begreep steeds beter waarom iets werkte of niet. Dat rommelen bleek geen zwakte, maar een noodzakelijke stap in leren programmeren.

Samenvatting

De belangrijkste opbrengst is niet een perfecte website, maar dat ik nu kan uitleggen waarom iets werkt of niet, fouten zie als informatie en zelfstandig code durf te analyseren en herstellen. Daarmee heb ik mijn digitale geletterdheid daadwerkelijk verdiept.
